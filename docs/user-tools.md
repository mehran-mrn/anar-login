# Account phone tools

Open **Anar → User tools**, then choose **Check mobile numbers**. Checking is read-only. The report groups accounts that are ready to transfer, already linked, or need review. Shared normalized numbers and inconsistent Anar/Digits values are held for manual review; accounts are never merged.

Both the WordPress submenu and the internal Anar link appear only while unmatched Digits phone records require review or migration and no completion receipt exists. A site without those records shows neither menu entry. This checks actual records, not whether the Digits plugin is installed. Administrators may still open a bookmarked tools URL for a manual account audit; it does not mention Digits or offer migration when no source data is present. Completing migration removes both links immediately. Canonical phone linking, source metadata changes, account deletion and site membership changes invalidate the shared cached hint without running a full account scan.

The Digits section appears only when `digits_phone` or `digits_phone_no` exists on a current-site account without a canonical Anar number, and there is no completed `anar_digits_migration_complete` receipt. An empty installation or a completed migration has no migration controls. Full detection runs only when the tools screen is opened or a scan is explicitly requested. No frontend scan, migration cron, or tools assets on unrelated admin pages are registered.

Eligible administrators receive one informational reminder linking to the tools screen. The first notice check uses one indexed source-existence query and caches its result in `anar_digits_migration_detected`; later admin pages do not repeat that source query. The per-administrator `_anar_digits_migration_notice_seen` marker is stored on first display, with a unique option claim preventing duplicate reminders from simultaneous admin tabs. Completion suppresses all reminders, including for administrators who have not seen one. Activating Digits or an actual write/deletion of its source phone metadata invalidates the cached detection result without resetting the seen marker. These metadata hooks only invalidate a hint; they do not scan accounts, run migration or make external requests. Finding source data on the tools screen also refreshes the positive cache. There is no frontend reminder or extra notification JavaScript.

After reviewing the preview, **Transfer eligible numbers** asks for confirmation and links Iranian mobile numbers to the same WordPress user IDs. Full `digits_phone` and split `digt_countrycode`/`digits_phone_no` are recognized automatically. Persian/Arabic digits are normalized. Existing canonical numbers, passwords, roles, orders and Digits source metadata are preserved. Billing phone data is not treated as proof of identity. Source rows with skipped Digits verification, invalid numbers or inconsistent values are excluded.

Work is batched in groups of 200. Reports are private to the requesting administrator and expire after 20 minutes. Import candidates are fingerprinted and checked again before writing; a newly claimed canonical number is rejected by Anar's existing serialized phone-linking path. A complete transfer saves a completion receipt and hides the migration section. Unresolved unlinked source records leave the migration incomplete so they can be corrected and checked again. Adding new Digits metadata after completion does not silently reactivate migration.

The administrator needs `manage_options` and `list_users`; transferring also requires `edit_users` and permission to edit each target account. AJAX actions check the admin nonce, report ownership, phase and batch offset. A per-report expiring lock rejects overlapping operations. Multisite source scans are restricted to current-site membership. Keep a database backup before an import.

Regression checks: `tests/Unit/UserMigrationTest.php`; run `tests/Integration/user-tools.php` through WP-CLI only on a disposable local WordPress installation. The integration fixture checks cross-batch conflicts, stale previews, additive linking, split source fields, preservation of credentials and roles, zero-query registration and completion gating.
